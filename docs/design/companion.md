# 伙伴小屋

> 2026-11-06。第一版的实现规格，以及之后的路线。调研和长期设计的底稿在 Drive `AI-workspace/dshgo-companion1/`（C1xx 调研、C2xx 设计、C3xx 后端约定）。

## 0. 结论

- **整页换模式，不是加挂件。** 从「切换主机」面板进入。这页是一个 Live2D 角色，上面叠字幕和输入条。现有的状态宠物（`pets.md`）不变，它仍然只表达 agent 在干什么。
- **活人感优先靠规则层，不靠模型。** 眨眼、视线、呼吸、闲置小动作、触摸反应、昼夜和问候都不花 token。模型只在用户开口时才调用。
- **Live2D 的东西不进 APK 和仓库。** Core 是 Live2D 的专有代码，框架和模型各有条款。它们打成素材包，用时才放进手机。App 里只有我们自己的舞台代码。
- **角色素材是数据，运行库是代码。** 运行库按写死的摘要校验，角色目录只收数据文件。所以以后用户自己导入角色时，别人的包不能在 WebView 里跑脚本。
- **两种对话方式，用户自己选（§6.3）。** 轻量：手机直接调模型，只聊天，不用启动引擎、不连主机。完整：当前主机上的一个普通会话，用 `dsh-go-companion-full` 预设，有主机的全部工具，开了手机操控时还有手机工具。

## 2. 结构

```
Flutter CompanionPage
  ├─ CompanionStage（WebViewController）── runJavaScript: stage.command({type, ...})
  │     ▲ JS channel DshCompanion: ready / error / touch / wake / mood / object / activity
  │     └─ http://127.0.0.1:<随机端口>/<随机令牌>/{app,pack}/...  CompanionServer
  ├─ 名牌、字幕、输入条（companion_chrome.dart）
  └─ chatProvider(sessionId) ── 普通会话 ── 当前主机上的 DSH
```

- **回环服务**：WebView 要 `fetch` 着色器和模型文件，`file://` 做不到。手机上任何 App 都能连回环端口，所以每条路径都以每次启动随机生成的令牌开头，没有令牌只有 404。页面关闭时服务也关闭。`app/` 只有固定的几个文件，`pack/` 只读且不出目录。
- **WebView 不拿权限**：`onPermissionRequest` 一律拒绝，页面只能导航到自己。麦克风留在 Flutter 一侧，用现有的 `VoiceInputController`。
- **CSP**：`script-src 'self' 'wasm-unsafe-eval'`，Core 的 WASM 需要后者。模型文字不进脚本，命令都是 JSON 编码的结构化消息。
- **一帧的顺序**（`StageModel.tick`）：恢复参数基线 → 保存 → `animate.before`（写视线、姿态、表情参数、动作、口型）→ 表情管理器 → 物理 → Pose → `animate.after`（尾巴）→ `model.update`。Framework 的 `getParameterIndex` 对不存在的参数会造一个虚拟索引，所以判断模型有没有某个参数要和 `getParameterCount` 比。

## 3. 素材包

**随包带一份**（owner 2026-11-06 的决定）：把 zip 放在 `app/assets/companion/whale-girl.zip` 再打包，App 里就带着它。第一次进小屋时自动解压（走和导入一样的校验，她「游过来」的画面里完成）；用户在菜单里移除后不再自己回来，设置页的主按钮变成「接她回家」，「导入别的素材包」退到第二。这个 zip 被 `.gitignore` 挡在仓库外：模型授权没确认前，只有本机打的包带它，CI 打的公开包没有。要让公开包也带，得先确认授权，再决定提交进仓库还是在 CI 里放进去。

```
pack.zip
├─ runtime/                      代码，摘要写死在 companionRuntimeDigest
│  ├─ live2dcubismcore.min.js    Live2D Proprietary Software License（RedistributableFiles.txt 列出的可再分发文件）
│  ├─ cubism-framework.js        Live2D Open Software License，由 build-pack.mjs 打包
│  ├─ shaders/*.frag|*.vert
│  └─ LICENSE-framework.md
└─ character/                    数据：.json .moc3 .png .jpg .jpeg .webp .wav .mp3 .txt .md
   ├─ character.json             可选，见下
   ├─ *.model3.json
   └─ ...
```

`tooling/companion/build-pack.mjs` 生成它并打印摘要。只含 `character/` 的包保留已装的运行库，这是以后「用户自己上传角色」的入口。

**Core 的版本**：Framework 5-r.5 要 Core 6.0.1，它来自 SDK 压缩包 `CubismSdkForWeb-5-r.5`。`cubism.live2d.com/sdk-web/cubismcore/` 上的 CDN 版本是 5.1.0，两者不兼容，`csmGetMocVersion` 会报错。

**`character.json`**（都可选，缺了用标准参数名和默认分区）：

| 键 | 含义 |
|---|---|
| `name`、`author`、`license`、`source` | 菜单底部如实显示 |
| `model` | 模型文件；缺省取第一个 `*.model3.json` |
| `framing` | `{zoom, y}` 默认取景 |
| `mark` | 漫符出现的位置，模型坐标 |
| `tail` | 尾巴的参数 ID，从根到尖 |
| `zones` | 触摸分区：`{id, from, to, xFrom?, xTo?}`，纵向是从头顶算的比例 |
| `emotions` | 情绪：`{expression, face: {参数: 值}, gaze: [x, y]}`，和默认表合并 |
| `actions` | 该模型专有的动作曲线，如 `wave` |

鲸鱼娘的配置在 `tooling/companion/whale-girl.character.json`。

## 4. 预设和人设

`cordis.patch.yml` 里 `--- shared rows ---` 以下的行，`rtbuild.py` 也会放进本机运行时的 overlay，所以本机和 `dsh plugin add dsh-go-bridge` 的远程主机都有这个预设。人设用 `prefix` + `complete: true` + `includeRuntimeContext: false`，只留人设，再带上压缩组。人设写了不声称是真人、不写色情内容、不发展恋爱情节、遇到自伤信号要放下角色认真回应。

**没有预设的主机**（旧运行时、没更新桥接的远程主机）：`CompanionSessions` 查不到预设就退回默认预设，人设放进第一条消息。这时她有工具，请求审批时页面上出现「有件事要你确认」，点了进普通对话。批准只能是真实点按，她说的话和语音都不算。

**会话隔离**：`companionSessionFilterProvider` 让她的会话不进抽屉，她的回复不发「做完了」提醒。需要用户处理的提醒照常走。

**旁白**：每条消息前加 `〔11月6日 周五 21:14，对方刚才摸了摸你的头〕`，告诉她时间和刚才的触摸。人设说明了这不是对方说的话。

## 5. 设计约定

- 气质按 `polish-guide.md`：玻璃表面、边距 12、顶栏 44、输入条里的圆键同心。这一页的水下场景、缓慢光束和轻微视差是例外，它就是这一页的内容，而且都是合成层变换，开销很小。系统关闭动画时全部停掉。
- 触摸反应立刻发生，不等网络。
- 低内存手机（不足 6 GB）纹理降到 2048。画布最多 2 倍像素。闲置 30 帧，有事 60 帧，睡着 12 帧。App 进后台时暂停。

## 6. 路线图

### 6.1 小房子第 1 期

依据 Pro 的 C204。不另做房间页：她本来就住在水下场景里，所以把场景的下半部分变成她的一角，三件东西摆在她身边。

| 物件 | 位置 | 点了以后（表演时长） | 主机上的活动 |
|---|---|---|---|
| 贝壳点心盘 | 她前面，左下 | 先看你（熟了才有），再看盘子，一块点心沿弧线飘到嘴边，她往盘子那边探身，吃到时点头、开心、摆尾（3.2 秒） | `snack`，45 秒 |
| 泡泡球 | 她前面，右侧 | 球飞到她脸旁边（不挡脸），她视线跟着球、开心、轻轻一跳，球弹回去；很熟时把球递还给你（3.6 秒） | `play`，90 秒 |
| 海草软垫 | 她身后，右下 | 她往软垫那边靠、身体微沉、犯困，软垫被压扁（1.2 秒） | `rest`，15 分钟 |

- **表演归页面，活动归主机。** 表演只在本机跑，不等网络；活动和结束时间由主机的快照决定（`vitals.activity`、`activityUntil`），剩余时间按快照里主机自己的 `asOf` 算，不用手机时钟。没有主机或主机不支持时，页面按同样的时长自己记一份。
- **一次只演一段。** 表演中再点物件，只回一个按压动画，事件照常记。
- **点按顺序**：前面的点心盘、泡泡球 → 她 → 她身后的软垫。所以软垫露出来的部分才算点中，点她身上永远是摸她。休息时整个模型往右偏，触摸的坐标换算会扣掉这个偏移。
- **名牌**写她在做什么（在吃点心 / 在玩泡泡 / 在软垫上歇着），活动结束时舞台通知页面换回来。她说话、在想、在听的时候这些优先。
- **旁白**带上刚才的事（「对方刚才给你吃了一块点心」），下一条消息里她能接上。
- **配色**跟着四个时段换，物件用场景的颜色变量，不是贴图。

### 6.3 轻量和完整两种模式

owner 的决定：「轻量的模式就只做对话，甚至连 dsh 内核都不用起；完整版就把 dsh 内核以及各种完整的工具调用、手机操控能力接上。」菜单里的「对话方式」切换，没选过时，连着主机用完整，没连就用轻量。

| | 轻量 | 完整 |
|---|---|---|
| 大脑 | 手机直接调 DeepSeek 官方 Messages 接口：`https://api.deepseek.com/anthropic/v1/messages`，`x-api-key` + `anthropic-version: 2023-06-01`，模型 `deepseek-flash`，`thinking: disabled`，流式。和引擎的 `@deepseek-ai/dsh-llm-deepseek` 同一个接口 | 当前主机上的 DSH 会话，`dsh-go-companion` 预设 |
| 要什么 | App 里存的 DeepSeek API Key（设置里填的那个，安全存储）。只用 DeepSeek 账号登录、没有 Key 时不能用 | 一台连着的主机 |
| 人设 | `companionPersonaCore` 做 system，和预设里的同一份 | 预设里的人设 |
| 对话记录 | 这台手机上的 `<伙伴目录>/light-chat.json`，存最近 80 行，每次带最近 24 行（同一方连续的行合并，开头是用户）。移除素材包不删它，「重新认识」删它 | 主机上的会话，菜单能打开 |
| 状态和记忆 | 这台手机上的 `<伙伴目录>/light-state.json`：`CompanionLocalStore`（packages/dsh_client，Pro C434/C436）跑和主机桥接同一套规则（C303），storeId、revision、冲突错误都一样，有和桥接 store 对拍的夹具。页面经 `CompanionKeeper` 两边通用 | 主机上的状态和「她记得的事」 |
| 工具 | 没有 | 主机的全部工具（0.2.2-rc.1 是 31 个），开了手机操控再加 13 个手机工具。权限用主机的默认设置，不受「自动批准命令」影响；要批准时页面出现「有件事要你确认」，点了到普通对话里处理。小屋里直接审批按 Pro C420/C422 做。以前那个只有人设、只读的会话不再复用，留在主机上，下次说话时开新的 |

- **出错时**：没有 Key、Key 被拒（401/403）、太忙（429 或 `overloaded_error`）各有一句；一个字都没回就失败的话，这句话放回输入框，记录里也不留。停止时她已经说出的部分留下。
- **两种模式共用一套回复处理**（`_onReply`）：标记只执行一次、字幕、口型、说完后的心情，都和完整模式一样。
- **切换**时丢掉正在路上的回复，不再打招呼，只换掉对话的去处。

### 6.4 主动邀请

依据 Pro 的 C451（判定核，原样合入）和 C452（接线合同）。你安静陪着她一会儿，她偶尔会问要不要一起在软垫上歇一会儿。不说出来、不出声、不震动、不抢焦点：输入条上方出现一张卡片，她看一眼软垫，软垫上隔一会儿冒两个泡泡。

- **什么时候问。** 页面在最前面（菜单、对话框、别的页面盖住都不算），App 在前台，舞台好了；她没在说话、想、听，没在吃点心、玩、歇着或睡着，屏幕上没有她的话或你的话，没有要你确认的事，输入框空着也没聚焦。这样连续 45 秒才问。一次来访最多一次（离开不到 30 分钟算同一次），24 小时最多两次，两次至少隔 6 小时。这次来访里你做过任何事（手指落在她身上、点东西、点输入框或打字、录音、发送、停止、开菜单、返回）就不再问；手指落下那一刻就算，不等手势认出来。
- **卡片。** 8 秒后自己走，底下一条细线从两头往中间收，显示还剩多久。用读屏时不自己走，也没有细线，有读屏的情况一变就按新情况重新计时。点**好呀**走软垫自己的入口：舞台演软垫被压的那一下（只表演，不回传事件），再像点软垫一样记一次 `rest`，她说一句（「嘿嘿，就歇一小会儿。」）。点**等会儿**她轻轻点头，不说话，之后 6 小时不问。不理、超时、离开、切模式都不算回答，什么也不记。卡片出现时提示气泡让位。
- **谁来管。** `companion_initiative.dart` 是 Pro 的纯 Dart 判定核，不碰 I/O。`companion_initiative_owner.dart` 是 App 级唯一的 owner：App 启动时读账本，按顺序写，只用两个一次性定时器（安静满 45 秒或墙钟门槛到了才醒，显示 8 秒到期），醒来只问判定核。页面实现 `CompanionInitiativeRoom`：每帧之后把当前情况交给 owner；票只在产生它的那次同步处理里挂上或丢掉，不排队。页面的身份是「这一页 / 模式 / 绑定 epoch / 舞台 epoch」，换了就收回旧卡，旧按钮点了也没用。
- **账本。** 一台手机一份，偏好 `companion_initiative_v1`：`{v:1, lastGreetingAtMs, inviteAtMs[], declinedUntilMs}`。读不出、格式不认识、有不认识的字段、记录的时间在未来，这次运行就不再邀请，也不改写它；写失败同样关掉，晚到的成功不会重新打开。切主机、切模式、重载舞台、重新认识都不清账本。
- **开关。** 菜单里的**主动邀请**，默认开，没读出来之前当作关。它和下面路线图的「主动开口」不是一回事：那是她用模型主动说话，还没做。
- **进门欢迎不用。** 判定核也能给进门欢迎，这一版页面一律丢掉：她进门时已经用自己的话打招呼了。
- **已知边界**（C452 §2.3）：卡片已挂上、账本还没写进去时 App 被强杀，重启后可能再问一次。测试里的生命周期一开始是空的，判定只认明确的「在前台」，所以页面测试先把它设成前台。

### 6.5 手感、作息、变熟、记忆、联动、声音、桌面小组件

owner 2026-11-06 定了这一轮全做。界面和舞台归主线，规则层和协议交给 Pro（ADDENDUM-06），下面写的是主线已经做的部分。

- **手感。** 从贝壳盘把点心拖出来：点心跟着手指，她盯着看，离嘴越近嘴张得越大；在嘴边松手就吃掉（和点盘子是同一个 `snack` 事件），别处松手点心飘回盘子、什么也不发。手指在她身上停 650 毫秒算拥抱：她朝手指那边靠过去、低一点头、冒爱心，发 `hug`（她的状态里记成 `pet`）。倾斜手机时礁石和水里的微粒挪几个像素，几秒后回到手机现在的握法；系统关掉动画时不动。视线跟手指原来就有。
- **作息。** 23 点到 5 点她犯困：眼皮更沉、动作更慢。清晨（5–8 点）进小屋，问候过后先伸懒腰再打哈欠。夜里早睡、多打哈欠原来就有。真正的作息规则（几点困、几点醒）等 Pro 的规则层。
- **变熟。** 亲近度分四档（`companion_bond.dart`，`stage.js` 里同一组线）：刚认识、渐渐熟悉（0.03）、熟起来了（0.10）、很亲近（0.30），和舞台原有的 0.025（先看你一眼再吃）、0.095（把球递回来）对齐。亲近度本身每 6 小时最多 +0.01。在小屋里时跨过一档：她蹦一下、开心、说一句，只这一次；进来时已经到了不算。菜单里「你们的关系」四颗珠子。熟起来以后摸头、拥抱各多一句更亲的话，哼歌更多；很亲近时偶尔朝你吐个爱心泡泡；刚认识时被抱会害羞。只在保存她状态的地方显示（轻量模式，或带桥接的主机）。
- **记忆。** 轻量模式每次回话前，把这台手机上确认过的记忆接在人设后面，注明是资料不是指令：置顶的在前，再按最近修改排，过期的不带，最多 12 条、1200 字。两秒读不出来就这次不带。完整模式的自动回忆在桥接层，交给 Pro。
- **联动。** 小屋开着时，她听状态宠物同一条事件线（`pet_signals` 的总线）：别的对话跑完、出错、等批准、有问题要问，她换个表情说一句（「『整理照片』那边跑完啦。」），下一句回复里能接上；在当前主机上的，还会出一个「去看看」胶囊，15 秒内点了直接打开那个对话。被停下的不提（是你自己停的）；一连串只说一句；她自己的话没说完时让着她；这些都不算你的动作，胶囊在时邀请也不出来。手机事件和通知等 Pro 的协议。
- **声音。** 小原生插件 `CompanionVoicePlugin` 调安卓系统的文字转语音，通道 `dsh/companion_voice`，没加新依赖。默认关；菜单「她的声音」打开时先确认系统能说中文，然后她用这个声音打个招呼，让你听到选的是什么；没有中文语音就提示去系统设置里装。短台词整句读，模型的回复按句子边流边读，说完读剩下的，重试不会重读。开着声音时嘴型跟着引擎报的正在读的字走（不报的引擎按整句的节奏）。你打字、发送、按停止、开麦、切模式、离开时立刻停；她说话时邀请等着。
- **外接声音。** 「她的声音」是单独一页：开关、来源三选一。手机自带（同上）；OpenAI 兼容接口（地址填到 `/v1`，App 接 `/audio/speech`，带 Key、模型、音色，请求 `response_format: wav`；OpenAI、硅基流动，以及大多数自建 GPT-SoVITS / CosyVoice / Fish-Speech / edge-tts 服务都认）；自定义 HTTP（地址和请求体里 `{text}` 替换成她要说的话，请求体里按 JSON 字符串转义；请求头每行一个；返回 JSON 时按 `data.audio` / `items.0.url` 这样的路径取 base64 或链接）。Key 和请求头存安全存储，其余存普通偏好。按句请求，入队就开始取，她读这句时下一句已经在路上；某句取不到或放不了，就用手机自带的声音读这一句，每次进小屋提示一次。返回 WAV（16 位 PCM）时，App 每 40 毫秒算一次响度，嘴型跟着真实音量开合（舞台的 `loudness` 命令）；其他格式按整句节奏。播放走 `CompanionVoicePlugin` 新加的 `play`，复用插件能力的 `ClipPlayer`（音频焦点、来电打断、迟到的回调都已处理），放完就删文件。试听按钮用当前填的内容说一句，失败时写出原因（HTTP 状态码、超时、不是音频、字段没找到）。
- **常用服务（预设）。** 来源里的第二项：选服务，只填 Key、点一个音色（也能手填音色 ID），MiMo 和 OpenAI 还能写说话风格（留空用默认的温柔少女音）。预设在 App 里换算成普通请求，不存下来，改预设对所有人生效。小米 MiMo：`POST https://api.xiaomimimo.com/v1/chat/completions`，`api-key` 和 `Authorization: Bearer` 两个头都带，模型 `mimo-v2.5-tts`，风格放 user 消息、她的话放 assistant 消息，`audio: {format: wav, voice}`，音频在 `choices.0.message.audio.data`（base64，24 kHz）；音色 冰糖、茉莉、苏打、白桦、mimo_default、Mia、Chloe、Milo、Dean。OpenAI：`gpt-4o-mini-tts`，风格走 `instructions`。硅基流动：`FunAudioLLM/CosyVoice2-0.5B:<音色>`。阿里云百炼：北京区 `qwen3-tts-flash`，音频是 `output.audio.url` 的链接（24 小时有效）。Key 每个服务各存一份，在安全存储里。小米 MiMo 还能**克隆声音**：音色那里切到「克隆声音」，选一段 5–30 秒、只有一个人说话的 mp3 或 wav（最大 7 MB，base64 后不超过 MiMo 的 10 MB），App 存到 `<伙伴目录>/voice-sample.<格式>`（写一半失败或格式不对不会留下文件），请求换成 `mimo-v2.5-tts-voiceclone`，音色字段放这段录音的 `data:` 地址；同一段录音只读一次、缓存在内存。小米的接口不记音色，所以每句话都会带上这段录音，界面上写明了，也写了只用自己或本人同意的声音。
- **她的设定。** 菜单「她的设定」一页管名字（最多 12 个字，留空用素材包的）、她怎么叫你、人设全文（最多 4000 字，从默认的那份改起，有「恢复默认」）。人设拆成两块：她是谁、怎么说话、哪些话不说（`companionPersonaDefault`，默认里带着 AI 身份、不写色情、遇到危险先关心这几条边界，整段交给用户改，删掉也行，owner 2026-11-07 定）；表情动作标记的格式和旁白说明（`companionPersonaRules`，App 固定接在后面，不显示、删不掉，否则舞台收不到标记）；轻量模式再加「没有工具」一句。轻量模式每次回话用拼好的人设做 system。完整模式的人设在主机预设里：内联人设的旧主机第一条消息带完整人设；有预设的主机，用户改过人设或称呼后，在下一条消息里带一段「对方给你改了设定……以这份为准」（只带用户那块），每个会话每次改动只带一次（按指纹记在偏好里）；名字仍每条消息带一句。主机预设直接接受每个会话的自定义人设由 Pro 做（ADDENDUM-06 #4）。从设定页改了名字，回到小屋时她蹦一下、说一句。
- **桌面小组件。** `CompanionWidgetProvider`：像素小鲸鱼（平时、夜里睡着、很熟以后笑着的三帧，按 4 倍最近邻放大）、名字、亲近珠子、她在做什么、她最后说的话（12 小时内）。App 在她的状态变化、说话、回复说完时经 `dsh/companion_widget` 发过来；两次来访之间小组件只随钟点在醒着和睡着之间切换、让活动到点结束。点一下走 `dshgo://open/companion` 打开小屋（这个页面链接是为小组件加的）。
